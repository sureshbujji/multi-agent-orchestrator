# Multi-Agent Orchestrator

I built a small but complete multi-agent system in Python that designs a test
plan for a login API using a **Planner → Worker → Critic** pattern, with all
agents communicating through a shared **blackboard**. The agent "brains" are
deterministic mock implementations (rule/template-based — no API calls, no
randomness), but the architecture is genuinely real: task decomposition,
message-passing orchestration, bounded rework loops, and run metrics all work
end to end and are covered by tests.

## Architecture

```
                        +----------------+
                        |   BLACKBOARD   |
                        |  task / plan / |
                        | artifacts /    |
                        | reviews /      |
                        | messages /     |
                        | iterations     |
                        +-------+--------+
                                ^  |  read / write
        plan_proposed           |  v   (every handoff is a message)
  +----------------+     +------+-------+
  |     PLANNER    |---->| ORCHESTRATOR |
  | decomposes the |     | drives the   |
  | task into      |     | loop: assign |
  | subtasks       |     | -> review -> |
  +-------+--------+     | revise       |
          |              +------+-------+
          |                     |
          v                     v
  +----------------+     +----------------+
  |     WORKER     |     |     CRITIC     |
  | executes one   |---->| reviews the    |
  | subtask, posts | artifact_submitted  | artifact vs its  |
  | an artifact    |     | acceptance     |
  +----------------+     | criteria       |
                         +----------------+
```

Message flow for one subtask (all logged on the blackboard):

```
orchestrator -> worker : work_assigned
worker       -> critic : artifact_submitted
critic       -> worker : review_posted (verdict: rework)
orchestrator -> worker : revision_requested (with critic feedback)
worker       -> critic : artifact_submitted (revised)
critic -> orchestrator : review_posted (verdict: accept)
orchestrator -> all    : subtask_accepted
```

Rework is bounded: each subtask gets at most `max_rework` (default 2) revision
cycles. A subtask that still fails review after the budget is exhausted is
marked `failed` — the loop can never run forever.

## Quickstart

```bash
pip install -r requirements.txt   # pytest
python -m pytest -q               # 19 tests
python src/demo.py                # run the demo
```

The demo runs the task **"Design a test plan for a login API."** The planner
decomposes it into four subtasks (auth flows, negative/edge cases, security,
performance); workers produce markdown test-case tables; the critic enforces
concrete acceptance criteria (minimum case counts, required sections,
required keywords such as "sql injection" and "rate limiting"). The security
subtask is flagged hard, so its first draft is deliberately thin and exercises
the full rework path.

Outputs:

- `reports/run_report.json` — full transcript: task, plan, messages,
  artifacts, reviews, iterations, statuses, metrics
- `reports/run_summary.md` — human-readable summary

Re-running the demo produces a byte-identical transcript (no timestamps — the
message log uses a monotonic sequence counter):

```bash
python src/demo.py
cp reports/run_report.json /tmp/run1.json
python src/demo.py
diff /tmp/run1.json reports/run_report.json   # no output: deterministic
```

## Roadmap

- **Real LLM backends**: swap the mock brains for LLM calls behind a common
  `Brain` interface (OpenAI / Anthropic keys are stubbed in `.env.example`);
  keep the mock brains as the offline test double.
- **Parallel workers**: execute independent subtasks concurrently (the
  blackboard would need locking or per-subtask partitions).
- **Richer critics**: rubric-based scoring, severity levels, and
  auto-escalation instead of binary accept/rework.
- **Persistent runs**: store transcripts in SQLite so runs can be resumed,
  compared, and diffed across code changes.
- **Human-in-the-loop**: pause on `subtask_failed` and let a human approve a
  manual fix or extend the rework budget.
